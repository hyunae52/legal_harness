# Security policy

## Supported scope

Security fixes target the current `main` branch and the currently deployed
release identified by `/health`. Older commits and local installations are not
supported after a fixed release is available.

## Reporting

Do not include credentials, personal data, client facts, or exploit details in
a public issue. Open a public issue titled `Security contact request` with no
technical detail. A maintainer will arrange a private channel before receiving
the report. If GitHub private vulnerability reporting is enabled, use
`Security` -> `Report a vulnerability` instead.

Include the affected commit or deployed version, the reachable endpoint, the
impact, and minimal reproduction steps. Never test availability attacks or
submit real taxpayer data to the public service.

## Disclosure

The maintainers will confirm receipt, assess impact, prepare a tested fix, and
coordinate disclosure. This limited beta has no guaranteed response time or
uptime commitment.
