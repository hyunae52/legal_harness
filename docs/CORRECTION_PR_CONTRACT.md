# 대화 중 발견한 오류의 교정 PR

2026-09-20 사용자 요청: “논지에서 밀리거나 다른 증거가 확실히 나오면 PR하시겠습니까”라고 제안하고, 동의하면 실제 PR을 생성한다.

범위는 법령·해석의 정정 근거와 재발 방지 점검 항목을 담는 **교정 자료 PR**이다. 사용자의 AI가 반박을 검토하고 준비 도구를 호출한다. MCP는 호출되지 않은 대화 전체를 볼 수 없으므로 모든 모델의 자발적 호출을 강제한다고 주장하지 않는다. 기존 실행 코드 자동 패치·별도 AI worker는 이 경로와 구분하며, 작성 AI의 평가를 독립 AI 승인으로 표시하지 않는다.

## 사용자 흐름

1. AI가 반박·새 근거를 비교하고 기존 답변의 정정 필요성을 인정한다.
2. 개인정보를 제외한 공개 가능한 오류 요지, 정정, 출처와 다음에 확인할 항목을 준비한다.
3. 서버가 게시할 내용을 고정하여 “이 정정 내용을 GitHub PR로 제안할까요?”라고 질문하도록 반환한다. 이 단계는 GitHub에 쓰지 않는다.
4. 사용자가 동의하면 고정된 제안에 대해서만 draft PR을 만든다. 아직 별도 AI 검수·사람 검수 전임을 PR 본문에 표시한다.
5. 사용자는 PR 링크에서 검수한다. 서버는 머지하지 않는다. 머지된 교정 자료만 이후 검색의 참고 근거로 제공하며 법률 검증 완료로 바꾸지 않는다.

| CP-02 | 동의·고정된 제안 hash·nonce·동일 actor가 없으면 생성하지 않는다 | 서비스 모듈 |

| CP-12 | 교정 PR 설정·초기화 실패가 기존 인증 법령 조회를 중단시키지 않는다 | production factory + HTTP 조회 경계 |
| CP-13 | 고정 base의 같은 파일 경로가 있으면 쓰기 전에 차단한다. 새 commit도 JSON 한 파일 추가인지 확인한 뒤 branch/PR을 게시한다 | GitHub HTTP adapter + 경로 충돌·변경 범위 주입 |
| CP-14 | 검증 시간 초과 전에 확인한 머지 이벤트를 건별로 영속 저장하고 재시작 후 이어간다. 실패한 미검증 PR은 이미 확인한 main 자료의 재확인을 막지 않는다 | 60건 + 실제 refresh deadline + 재시작 + 개별 API 실패 |
| CP-15 | Actions의 식별자 원문 조회도 질문에 맞는 교정 자료를 붙인다. upstream 인수는 변경하지 않고 미머지·변경·만료 자료는 제외한다 | 인증 HTTP + 실제 조회·GitHub adapter |
| CP-16 | 생성 응답 유실 뒤 PR이 닫히거나 머지돼도 동일 create 재전송이 기존 PR 상태 복구를 막지 않는다. 이전 버전에서 잘못 차단한 기록도 읽기 전용으로 복구하며 추가 GitHub 쓰기는 없다 | 실제 GitHub HTTP adapter + 종료 상태 2종 + 영속 기록·재시작 |

운영은 기존 단일 GCE 서비스 프로세스와 권한 제한된 영속 상태 디렉터리를 사용한다. 프로세스 내 동시 쓰기를 직렬화하고 실제 외부 작업 전 intent를 저장한다. 공유 접속키는 공유 actor이며 개인 계정별 비공개 저장소라고 안내하지 않는다. 자료와 URL은 검수 대상 데이터이고 실행하지 않는다. API 키·법제처 키·임의 사건 원본을 PR에 싣지 않는다. 사용자의 동의는 호출 클라이언트가 전달하며, 서버가 독립적으로 사람의 발언을 인증한다고 주장하지 않는다.

별도 AI 검수와 코드·테스트 자동 패치까지 포함하는 전체 B의 완료 조건은 기존 명세를 유지한다. 이 기능의 draft PR 생성 성공을 B 전체 완료로 보고하지 않는다.

동의 hash는 공개 JSON 자료와 대상 저장소·base branch를 함께 고정한다. 이 문서의 본문 대조는 commit에 담긴 JSON 파일을 뜻하며, 사람이 편집할 수 있는 GitHub PR 설명(`pr.body`)의 동일성은 보증하지 않는다. `merged`는 GitHub 머지 이벤트를 뜻하며 머지 주체가 사람인지까지 판별하지 않는다. 동일 경로 충돌은 `publication_blocked`로 확정 차단한다.

## 검사 기록

- RED: `node --test tests/correction-pr.test.mjs`에서 CP-07 실패. 기존 MCP 도구 목록에 `prepare_correction_pr`가 없다는 사용자 계약 위반을 확인했다. import/fixture 오류가 원인이 아니었다.
- GREEN: 같은 명령 통과. 영속 상태·동의·일일 한도·재시도·머지 반영 시험을 포함한 두 correction 시험 파일 9개가 통과했다.
- 실제 Octokit HTTP adapter를 로컬 GitHub HTTP fixture와 연결하여 JSON 한 파일만 추가, draft 생성, PR 생성 후 응답 유실, 같은 PR 대조, 변경된 branch 거부를 검사했다. 실제 GitHub 운영 생성 증거와는 별개이다.
- 전체 회귀: `npm run review` 85/85, skip 0. 기존 Actions schema 경로 기대값 변경은 새 교정 작업 3개의 추가 요구사항을 반영한 것이며, 실제 생성 작업이 consequential인지 추가 검증했다.
- 영속 저장은 파일 fsync 후 rename하고 Linux 운영 환경에서는 디렉터리도 fsync한다. 재시작 시험은 실제 전원 장애 시험을 의미하지 않는다. 조회의 `merged` 상태는 GitHub 머지와 main 파일 일치만 확인하며, 별도 AI 승인이나 법적 정답을 뜻하지 않는다.
