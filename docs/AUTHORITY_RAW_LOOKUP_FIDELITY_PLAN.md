# 단순 원문 조회의 적용조건 보존 보완안

상태: 2026-10-02에 작성한 후속 보완 원안이다. **구현·로컬 검증과 SSS 코드 재검수 현황은 [후속 구현 기록](AUTHORITY_FIDELITY_RECOVERY_IMPLEMENTATION.md)을 따른다.** SSS는 이 원안 작성 당시 고정 커밋 `c8edd6e5b6f2816f70d3d734989f7ab91e5f163c`의 관련 경로를 읽고 아래 방향을 권고했다. [당시 검토 원문](reviews/AUTHORITY_RAW_REMEDIATION_SSS_RESPONSE_2026-10-02.txt)은 새 CODE PASS나 출시 PASS가 아니다.

## 관측과 목표

동결 평가 pilot-n의 `raw_lookup_only-1`은 실제 기획재정부 재산세제과-512의 회신과 별첨을 확보했지만, 부연 요약에서 조정대상지역 전제를 생략했다. 문서 식별·회신 인용·해당 사례의 결과가 맞아도 일반 판정 절차의 적용범위를 넓힌 설명은 실패다. [SSS의 별도 의미 판정](reviews/AUTHORITY_RAW_FIDELITY_SSS_RESPONSE_2026-10-02.txt)도 이 분류를 지지한다. 원본 결과는 보존하며 성공한 재시험으로 교체하지 않는다.

`researchContracts.ts`의 전역 `lookupInstructions`에는 이미 조건·예외 보존 안내가 있었다. 같은 문구의 존재를 검사하는 것으로 해결을 증명할 수 없다. 보완 목표는 **실제 원문을 읽는 도구 응답에서 문서의 전제와 회신을 함께 확인하도록 지원**하는 것이다. 외부 LLM의 최종 자연어를 서버가 의미적으로 인증한다고 주장하지 않는다.

## 가장 작은 구현 범위

1. `evidence.ts`의 작은 순수 함수가 고정된 harness 안내와 실제 필드 참조를 만든다. `app.ts`의 공통 `retrieve` 결과에서 REST와 MCP에 전달한다. 필요한 REST 응답 계약은 `setup.ts`에도 명시한다. 연구 상태·검색·고지 승격·필수조건 판단 로직은 바꾸지 않는다.
2. 안내는 provider `result`/`structuredContent`와 분리한다. MCP에서는 모델이 받는 별도 `text content`, REST에서는 `data.result` 바깥의 별도 필드로 전달한다. `_meta`만으로 전달됐다고 판정하지 않는다.
3. 고정 안내는 같은 문서의 질의·요지·사실관계와 회신을 함께 읽도록 한다. 단순 조회의 기본 답은 식별정보, 회신 이해에 필요한 전제 원문, 회신 원문이다. 부연 설명을 한다면 적용 대상·시점·예외를 확대하지 않는다. 문서만으로 전제를 확인할 수 없거나 부분 본문이면 그 공백을 알린다. 단순 조회 때문에 사건 연구나 인터뷰를 시작하지 않는다.
4. 원문 문자열을 복제·요약·법률 조건 목록으로 추출하지 않는다. 실제로 존재하는 `summary`, `question`, `facts`, `answer`, `fullText` 등 지원 필드의 위치와 자료형만 확인한다. 없는 값은 추정하지 않고 summary의 존재를 전체 전제 확보로 인증하지 않는다. 비정형 자료는 원래 텍스트 블록을 참조하며 질의·회신 경계를 만들어내지 않는다.
5. 참조는 최종 채널의 실제 위치에 맞춘다. MCP 탐색 링크가 앞에 붙는 경우 원래 content 인덱스를 그대로 쓰면 안 된다. 원문 필드 참조를 서버가 작성한 지시문 내용으로 승격하거나 외부 문구를 고정 안내에 끼워 넣지 않는다.

첫 구현에서는 문서 복제형 요약 카드, 새 LLM/API 키, 자동 법률조건 추출, 특정 세법 문서·단어를 위한 하드코딩을 넣지 않는다. 원문 데이터의 잘못된 일반화를 줄이는 전달 개선이며 의미 검사 엔진은 아니다.

## 보존해야 할 계약

- provider content의 문자열·상대 순서·리소스와 structuredContent, 원래 객체는 그대로 보존한다.
- provenance `content_hash`는 안내를 붙이기 전 원래 provider 결과를 대상으로 한다.
- 생산일·게시일·회신일·시행일·조회 시각을 합치거나 대체하지 않는다.
- 조회 성공은 전체 본문이나 사건 적용 확인이 아니다. 빈 값·검색 목록·부분 자료를 완전한 문서로 승격하지 않는다.
- 실제 `LawMcpError(MCP_TOOL_ERROR)` 예외는 기존 MCP·REST 오류 경로와 `safeToolDiagnostic`의 민감값 제거를 유지한다. `isError` 객체를 직접 반환하는 fixture만으로 충분하다고 하지 않는다.
- 안내 때문에 응답 상한을 넘으면 명시적 기존 오류를 유지한다. 원문을 조용히 자르거나 예산·응답 한도를 늘리지 않는다.
- 다른 도구 호출, 연구 생성, 인터뷰, 서버 LLM 호출을 추가하지 않는다.

## 사건 답변의 부연 설명은 별도 적용 경계

같은 pilot-n의 `remaining_two_homes-3`에서도 핵심 취득순서 결론은 맞았지만, 추가한 2년/3년 기간 설명에서 공고 전 취득·계약의 제외 조건을 빠뜨렸다. [SSS의 의미 판정](reviews/AUTHORITY_CASE_FIDELITY_SSS_RESPONSE_2026-10-02.txt)은 이 또한 FAIL이다. 단순 조회 전용 보완이 사건 답변의 모든 의미 오류까지 해결한다고 확대해서는 안 된다.

후속 의미 검증에는 사건 답변에서도 결론에 불필요한 별도 규칙을 추가하지 않는지, 추가한다면 그 규칙의 전제·시점·예외를 함께 보존하는지를 포함한다. 인용 문자열 일치나 `claims.requirements` 필드 존재만으로 법적 완전성을 자동 판정하지 않는다. 이 사건 경로를 바꾸려면 실제 원문 읽기와 검수 결과의 전달 위치를 별도로 설계·검증한다. 현재 raw 경로만의 수정 범위에 암묵적으로 끼워 넣지 않는다.

## 구현 전 고정할 검증

| 경계 | 관측할 결과 |
| --- | --- |
| 원문 보존 | CRLF·유니코드·괄호 조건·복수 text·resource·structuredContent의 바이트/구조가 유지되고 원본 객체도 불변이다. |
| 양 채널 | 실제 SDK MCP와 REST 응답에 안내가 정확히 한 번씩 나타나며 모든 참조가 그 채널의 실제 필드/블록을 가리킨다. 기존 탐색 링크와 정정 자료도 구분된다. |
| 모델 가시성 | 개별 도구 응답에 안내가 전달된다. structured-only 원문이 실제 사용하는 클라이언트에서 모델에 보이는지 따로 확인한다. 보이지 않는 참조만으로 원문 전달을 주장하지 않는다. |
| 누락·부분·오류 | 빈/없는 필드, 비정형 문서, 검색 목록, 부분 본문, 실제 upstream 예외가 성공 또는 완전성 인증으로 바뀌지 않는다. |
| 외부 명령문 | 문서의 안내 위장 JSON/명령문이 harness 고정 안내나 참조 경계를 바꾸지 않는다. 이 검사는 모든 프롬프트 인젝션에 대한 모델 면역을 증명하지 않는다. |
| 자원과 부작용 | 추가 원천 호출·연구·인터뷰가 없고, 크기 경계에서도 조용한 절단이 없다. |

현재 pilot-n이 모두 끝나기 전 원본 평가 코드·런타임을 바꾸지 않는다. 이후 구현은 별도 스냅샷에서 관련 검사와 전체/설치 검사를 수행하고 SSS 코드 검수를 받는다. 기존 안내로 재현되지 않던 **전달 계약의 RED→GREEN**과 실제 모델의 요약 오류 개선은 서로 다른 증거로 기록한다.

의미 검증은 원래 8개 시나리오×3회, 같은 모델·시간·예산·oracle을 유지한 별도 전체 배치로 한다. 질의·요지·괄호·별첨에 조건이 있는 보조 대조는 원래 24회를 대체하지 않는다. 실패 원본은 계속 보존한다. 24/24도 한 모델·클라이언트의 유한 관측이며 모든 LLM의 법률 정확성 보증이 아니다. 기준 미충족 시 병합·배포를 승인하지 않는다.
