중간 검수 결론: 설계 보완 1건과 구현 수정 5건이 필요합니다

현재 코드는 남은 페이지를 미완료로 남기는 안전성은 지키지만, 너무 넓은 검색 → 모든 후보 원문 조회 → 조회한 자료마다 후속 검색으로 작업이 늘어납니다. 여기에 대체 성공과 revision 재연결 문제가 겹쳐 정상 사건도 완료하기 어렵습니다. 반대로 후속 자료군과 개정 조회에는 실제로 확인한 범위보다 완료 상태가 넓게 인정되는 경로가 있습니다.

아래는 읽은 소스에 대한 정적 검수와 구체적인 실패 반례입니다. 제가 테스트를 실행하거나 운영 장애를 재현한 결과는 아닙니다.

후속·개정	원문을 가져왔다는 이유만으로 모두 후속 검색 대상으로 만들지 않습니다. 채택한 핵심 법리, 발견한 직접 관련 필수 후보, 후속 상태가 적용·배제 판단을 좌우하는 자료에 연결합니다. 새로 발견한 자료가 핵심 근거로 승격되면 의무를 추가하고, 같은 문서·같은 범위는 중복 실행하지 않습니다.

실행 전에 서버가 필수 조사와 보조 탐색을 구별해야 합니다. 넓은 앵커 탐색을 수행했다는 이유만으로 그 결과 전체가 자동으로 사건의 필수 조사 범위가 되어서는 안 됩니다. 반대로 결과가 많거나 실패했다는 이유로 이미 필수로 등록한 검색을 보조 탐색으로 낮춰서는 안 됩니다. 기존 넓은 검색의 partial과 발견 이력은 그대로 남깁니다.

후보 선별도 필요합니다. 현재 계획의 **“같은 조문이 관측되면 원문 필수”**를, 해당 조문 안의 구체적인 요건·시점·특례 범위와 연결된 필수 후보 기준으로 보완해야 합니다. 같은 조문이라는 이유만으로 다른 특례 자료까지 모두 필수화하지 않되, 범위 밖 판정에는 서버가 확인할 수 있는 필드·근거 위치를 남겨야 합니다. 정보가 부족하거나 직접 관련 가능성이 남으면 원문 검토 또는 미완료입니다. non_major, 최신순 상위 N건, 모델의 “무관함” 선언만으로 닫는 방식은 제외합니다.

예산은 후보를 잘라내는 기준이 아니라 실행 계획의 수용 가능성 검사에 사용해야 합니다

다음 정도로 36회 목표·4회 여유를 두고 조정할 수 있습니다. 이는 새 설계 제안이지 실측값이 아닙니다.

2. 중요 지적 — 최대 6개
F-1. P1 · 계획 보완 + 구현 반영 — 모든 후보와 모든 조회 원문이 추가 의무를 발생시킵니다

근거: src/researchCoverage.ts:107–132, 167–185, src/research.ts:159–175.

candidateGaps()는 해당 쟁점의 모든 후보에 원문과 authority 검토를 요구합니다. 후속 의무 생성도 핵심 근거인지 판단하지 않고, 현재 revision의 비법령 원문을 순회합니다. 자동 실행기는 기존 필수 검색을 먼저 처리하고 이후 후보를 조회하며, 조회한 원문 때문에 다시 후속 의무가 생깁니다.

실패 경로: 넓은 검색에서 후보 다수 발견 → 모든 원문 요구 → 원문마다 후속 검색 추가 → 새 후보·원문·후속 의무 증가 → 40회·32단위·후보 원장 한도에서 종료 불가능. 페이지 수만 늘려도 해결되지 않습니다.

최소 수정: 앞의 자료군별 recipe·객관적 후보 선별·핵심 후속 의무 조건을 계획에 고정한 뒤 구현합니다. nextCandidateStep()도 단순 발견 순서가 아니라 필수 여부·관측 권위·직접 연결 관계에 따른 순서를 사용해야 합니다. 정상 대조와 대표 실패를 모두 같은 정책으로 평가해야 합니다.

F-2. P1 · 구현 버그 — 후속·개정 의무가 실제 확인 범위보다 넓게 완료됩니다

근거: src/researchCoverage.ts:35, 116–122, 149–170, src/legalApplicability.ts:82–89.

두 경로를 확인했습니다.

심판 후속 경로: 후속 recipe 선택은 administrative_interpretation이면 administrative, 나머지는 전부 court입니다. 따라서 tax_appeal도 법원 검색으로 갑니다. 그 법원 검색이 정상 0건이면, 해당 authority의 후속 검색이 완료된 것으로 인정될 수 있습니다. 심판 관련 후속 자료를 검색한 증거는 아닙니다.

개정 경로: amendment 의무는 search_law(query=법령명)으로 생성됩니다. 그런데 법령 검색 후보는 후보 원장 추가에서 제외됩니다. 결과에 다른 MST·버전 후보가 있어도 처리 대상으로 연결되지 않아, 법령 목록 조회만으로 completed_no_candidate가 될 수 있습니다.

최소 수정: 후속 의무를 자료 종류·확인 목적별로 분리하고, 다른 자료군의 성공이 대신 충족하지 못하게 해야 합니다. 개정 검색에서 발견한 버전·MST는 적용 법령과의 대조 작업으로 연결합니다. 지원 경로가 없으면 명시적 공백이어야 합니다.

검증 예: 법원 검색은 0건이지만 심판 후속 자료는 존재하는 경우, 법령 검색에 새로운 MST가 있지만 그 버전·부칙을 읽지 않은 경우를 각각 완료로 인정하지 않아야 합니다.

F-3. P1 · 구현 버그 — 같은 의무를 충족한 대체 성공도 과거 실패를 해결하지 못합니다

근거: src/researchCoverage.ts:89–100, src/research.ts:99–104, src/researchReview.ts:98–100.

superseded()는 같은 도구·같은 arguments_hash·같은 목적·같은 쟁점 집합의 성공만 인정합니다. 실제 attempt에는 의무·단계·수락 범위의 연결이 저장되지 않습니다.

실패 경로: get_tax_document가 실패 → 다른 허용 조회 도구로 동일 문서 신원과 필요한 원문을 확보 → 필수 문서 공백은 해결됐지만 원래 실패는 계속 incomplete_attempts → 최종 답변은 계속 차단됩니다. 제공자 장애 시 승인 계획의 대체 경로가 작동하지 않습니다.

최소 수정: 서버가 attempt를 의무·단계·필요 범위에 연결하고, 대체 성공의 문서 신원·버전·본문 범위 또는 검색 범위가 실제 요구를 충족했는지 확인해야 합니다. 확인된 경우에만 resolved_by_attempt_id를 부여합니다. 단순히 “다른 성공이 하나 있음”으로 지우면 안 됩니다.

검증 예: 동일 문서의 검증된 대체 원문은 실패를 해소하고, 다른 문서·다른 날짜 역할·부분 본문은 해소하지 않는 쌍으로 검사합니다.

F-4. P1 · 구현 버그 — revision 변경 후 원문은 공간을 차지하지만 재사용할 경로가 없습니다

근거: src/research.ts:190–209, 225–230, src/researchCoverage.ts:85, 104–106, src/researchReview.ts:9–10, src/researchContracts.ts:85–96.

계획·사실 변경은 기존 evidence와 manifest를 보존합니다. 하지만 coverage와 실제 인용 검사는 현재 revision의 evidence만 사용하며, 공개 연구 계약에는 기존 불변 원문을 현재 revision에 재연결하는 동작이 없습니다.

실패 경로: 원문 32단위를 확보한 상태에서 사실 하나 보완 → revision 증가 → 기존 원문과 앵커가 현재 검수에서 제외 → 원문은 여전히 32단위 한도를 차지 → 재조회도 거절. TTL 안에서 정상 복구할 경로가 없습니다.

최소 수정: 불변 원문·manifest와 revision별 신원·적용 연결을 분리하고 재연결 경로를 제공해야 합니다. 원문 바이트를 중복 저장하거나 과거 검색 성공을 새 검색으로 승격하지 말고, 적용 판단과 필요한 현재 검색은 다시 검증합니다.

검증 예: 32단위 보관 후 사실 보완에서도 필요한 원문을 중복 저장하지 않고 재검토할 수 있어야 합니다. 이전 검수 효력과 조회 시각은 갱신한 것처럼 표시하면 안 됩니다.

F-5. P1 · 구현 버그 — 출처 필드끼리의 권위 충돌을 일부 놓칩니다

근거: src/researchIdentity.ts:15–34, src/legalApplicability.ts:70–74.

기관 판단은 doc.issuingAgency ?? doc.court 중 하나만 선택합니다. 두 필드는 observations에 모두 남지만, 둘 사이의 충돌은 분류에 반영되지 않습니다.

실패 경로: 제공자가 issuingAgency=대법원, court=서울고등법원, documentType=판결처럼 상충하는 메타데이터를 반환하면, 선택된 앞 필드만으로 supreme_court / observed가 될 수 있습니다. 모델이 같은 종류를 선언하면 종류 대조도 통과합니다.

이는 기존 F-03의 단순 모델 재선언 차단과는 별개입니다. 그 차단은 추가됐지만, 관측 정보 자체의 충돌 처리가 부족합니다.

최소 수정: 기관·법원 등 독립 관측값을 각각 평가한 뒤, 서로 다른 확정 권위가 나오면 conflict로 남겨야 합니다. 미상 값이 추가 정보로 보완되는 경우와 실제 충돌도 구별합니다.

검증 예: 두 기관 필드가 상충하면 차단하고, 한 필드가 없고 다른 필드가 명확한 정상 응답은 불필요하게 차단하지 않아야 합니다.

F-6. P1 · 구현 버그 — 세션 만료가 진행 중 호출의 예약까지 먼저 회수합니다

근거: src/research.ts:50–69, 101–120, src/koreanLawClient.ts:135–199.

purge()는 만료 세션을 Map에서 즉시 삭제합니다. 전체 예산은 그 Map 안의 저장량·예약량만 합산합니다. 그러나 해당 세션의 provider.callTool()은 세션 만료와 별개로 계속 진행할 수 있습니다.

실패 경로: TTL 직전에 조회 시작 → 조회 중 세션 만료·purge → 살아 있는 호출의 임시 예약이 전체 회계에서 사라짐 → 새 작업이 그 공간을 사용 → 지연 응답과 새 작업의 자원이 겹칩니다. 오래된 콜백의 상태 쓰기를 거절하더라도 진행 중 자원의 예산 누락은 해결되지 않습니다.

최소 수정: 세션의 논리적 만료와 실행 중 자원의 반환을 분리해야 합니다. 작업 ID·소유 토큰에 연결된 메모리 예약을 별도로 유지하고, 실제 호출·수신·정리가 끝난 뒤 해당 작업의 예약만 반환합니다. 새 DB는 필요 없습니다.

검증 예: TTL 직전 시작한 지연 호출을 미완료 상태로 둔 채 만료 후 새 작업을 접수해, 이전 예약이 계속 합산되는지 확인합니다. 지연 정리가 새 작업의 예약·busy를 건드리지 않아야 합니다. OOM 발생을 실측했다는 지적은 아닙니다.
