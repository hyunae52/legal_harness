## 검수 범위와 증거

Chrome의 정상 Chat 모드에서 Pro 선택과 정확한 `Simdorei Local Project Oauth` 연결을 도우미로 확인했다. 최초 연결 검증 실패 후 허용된 한 차례 재시도가 성공했다. 새 검수 대화에서 최초 요청 1회에 대한 완료 응답을 받았고 후속 질의는 보내지 않았다. UI의 모델 표시는 Pro이며 구체적인 기반 모델 ID를 추정하지 않는다.

Pro는 `sim-pc-5060` 및 `C:/repos/simdorei/legal_harness`를 확인하고 MCP 파일 읽기로 계획 286줄·증거 JSON 83줄과 관련 소스를 읽었다고 보고했다. 계획과 증거의 반환 해시가 요청값과 일치했다. Codex도 로컬 파일 해시와 Pro가 보고한 소스 해시를 대조해 모두 일치함을 확인했다.

## 유지하는 한계와 다음 단계

- 이번 검수는 계획 검수다. 법률적 정답, 운영 배포 상태, 제보된 5.6 Sol/xhigh의 실제 호출 경로를 검증한 것이 아니다.
- 서버는 등록된 쟁점의 정해진 조사 수행과 관측 신원·연결을 검사한다. 올바른 쟁점 선택·법리 적용·원천 인덱싱·외부 모델의 발언을 모두 인증하지 않는다.
- 정상 0건·구법 해석 판례·법령 개정·단순 조회를 구별하는 기존 원칙은 유지했다. 별도 서버 LLM·새 DB·사용자 수 제한을 필수화하지 않았다.
- 최초 반영 시점에는 수정본에 대한 별도 Pro 재판정을 받지 않았다. 이후 재검수는 아래에 별도로 기록한다. 코드 구현 단계에서는 RED/GREEN·실제 검색·예산·모델 파일럿 증거로 이 계약을 검증하고 최종 diff를 다시 검수해야 한다.
- 사용자 변경인 `README.md`, `NEXT_STEPS.md`와 소스 코드는 수정하지 않았다. PR·병합·배포도 수행하지 않았다.

검수 원문을 따르되 정확한 소스 대조와 구현 판단은 Codex가 담당했다. 최초 초안 검수 직후에는 추가 Pro 왕복을 사용하지 않았다.

## 사용자 요청에 따른 보완본 재검수 시도

이후 사용자가 보완본 재검수를 요청하여 같은 대화에 다시 연결했다. 대상 계획은 406줄, SHA-256 `b83ef972a2440a590919e3457c77f6a2cfd0383b38dd64ad780122ab5fbeaf4d`로 고정했다.

최초 검증은 모델 선택이 Medium인 상태에서 `failed_stage=pro_mode`로 실패했다. 같은 대화를 한 번 새로고침한 뒤 Pro 표시가 복구됐으나, 허용된 재시도는 `failed_stage=connector_match`로 실패했다. 마지막 화면에는 정확한 연결 이름이 보였지만 검증된 연결 완료로 간주하지 않았다. Chrome 자체는 사용 가능하다.

스킬의 재시도 후 검증 실패 시 전송 금지 규칙에 따라 **보완본 요청은 미전송, 새 Pro 응답은 없음**으로 기록한다. 기존 초안 검수 결과를 보완본 승인으로 승격하지 않았다. 요청문과 재개에 필요한 상태는 `.runtime/authority-coverage-review-20261001/pro-rereview-request.txt`, `pro-rereview-attempt.json`에 보존했으며 같은 Chrome 탭을 열어 두었다. 추가 코드 검사·구현·배포는 수행하지 않았다.

## 재요청 후 완료된 보완본 검수

사용자가 동시 Pro 사용에 따른 오류 가능성을 알리고 재요청을 지시한 다음 턴에, 위와 같은 대화·PC·폴더로 재연결했다. Chrome 사용 가능, 정확한 OAuth 연결, 정상 Chat 모드와 Pro 선택을 검증한 뒤 요청을 한 번 전송했다. 이번 연결에는 재시도가 필요하지 않았으며 다른 작업의 탭을 건드리지 않았다. 응답 완료 표시를 확인한 후 [보완본 검수 원문](AUTHORITY_COVERAGE_PRO_REREVIEW_2026-10-01.txt)을 보존했다.

## 집중 후속 검수 최종 판정

같은 대화에서 Pro·정확한 OAuth 연결·정상 Chat 모드를 다시 검증한 뒤 집중 후속 요청을 1회 보냈다. 연결 메뉴 인식 실패 후 이번 턴에 허용된 한 번의 재시도가 성공했다. 다른 검수 탭은 변경하지 않았다. 약 2분 45초 뒤 응답 완료 UI를 확인하고 [최종 Pro 응답](AUTHORITY_COVERAGE_PRO_FOLLOWUP_2026-10-01.txt)을 보존했다.

Pro 판정은 **계획 검수 통과 — 구현 착수 가능**이다. R-1·R-2 모두 해소, 앞서 해소한 P1-1·2·3·5 판정 유지, P1-4도 해소이며 추가 계획 차단 사유나 수정으로 생긴 계약 모순은 발견하지 못했다고 답했다. Codex는 이 판정을 채택한다. 원문 snapshot의 관측 근거와 용량 실패의 종료 계약이 각각 AC-28/29의 정상·실패 사례에 연결되었기 때문이다. 구현 통과나 법률 정답의 인증으로 확대하지 않는다.
