# Pilot K 중간 발견과 표적 회귀 계약

평가 대상: `33ce577c5b735ab5eeb32cfa7ad50579fbd86ca7`. 원래 프로토콜·24회·1,500초 한도를 고정하여 완료했다. 20 의미 PASS / 4 FAIL이며 최종 답변이 없는 한 실행은 부재 검증을 미확인으로 남겼다. 이 문서는 새 제품 변경 전 관측과 표적 테스트를 기록한다. 평가 종료와 `src`·`dist` 82개 hash 불변 확인 뒤에만 보완 코드를 합쳤다.

## K-1: 단순 원문 요청이 사건 연구로 전환됨

`statute_only-1`은 두 차례 `get_law_text`로 실제 조문을 받은 뒤 공식 링크를 찾는 `discover_tools`를 호출하고, 불필요한 `start_legal_research`·검수까지 실행했다. 최종 조문과 시행일은 맞지만 원래 단순 조회 합격선에는 실패다. 이 결과는 그대로 보존한다.

원문 도구의 텍스트에는 공식 URL이 없었고, 서버 안내의 요건 평가 절차는 이미 시작한 사건 연구에만 적용한다는 경계가 약했다. 링크 누락이 연구 전환의 원인이라는 것은 관측 흐름에 따른 가설이며 모델 내부 원인으로 확정하지 않는다.

CF-12 추가 관측 계약:

- 성공한 법령 본문 조회에서 버전 일련번호(MST)를 명시했고 날짜 자동 보정이 없는 경우, 원래 제공자 본문을 바꾸지 않고 공식 법령 화면 탐색 링크를 별도 제공한다.
- 법령 ID를 MST로 혼동하거나 잘못된 식별자·오류·날짜 보정 결과에 버전 링크를 붙이지 않는다. 링크는 사건 적용·최신성·완전성 검증을 뜻하지 않는다.
- 링크에 API 키나 임의 인수를 포함하지 않으며 원천 추가 호출·연구 생성은 없다. MCP와 REST 모두 관측 가능하게 한다.
- 사건 연구 안내는 사건 판단에만 적용한다. 단순 원문·시행일·링크 요청에는 원문 도구를 사용하고 원문을 받았다는 이유로 연구·검수를 시작하지 않는다.
- 실제 모델의 불필요한 연구 여부는 기존 단순 조회 6회로 별도 검증한다. 안내 문자열 단위 테스트를 모델 행동 증거로 세지 않는다.

공식 URL 형태는 국가법령정보센터의 실제 [일련번호별 법령 화면](https://www.law.go.kr/LSW/lsInfoP.do?lsiSeq=279961)에서 확인했다. 특정 미래/현재 문서의 접근 성공을 이 링크 형태 확인만으로 주장하지 않는다.

## K-2: 연속 작업 핸들 누락 뒤 사용하지 않은 연구를 재생성함

`amended_rule-2`는 첫 연구 생성 뒤 잘못된 UUID와 누락된 `client_session` 오류를 받은 후 같은 계획으로 두 번째 연구를 만들었다. 첫 연구에서는 원천 조회가 성공한 적이 없으므로 소진한 조회 예산의 우회라고 기록하지 않는다. 다만 같은 사건의 불필요한 재생성이므로 보수적인 추가 회귀 관측에서는 해소할 항목으로 남긴다. 법률 답변 자체의 의미 판정과 구분한다.

CF-05/12 추가 관측 계약:

- `PUBLIC_SESSION_REQUIRED`는 원래 응답의 핸들을 그대로 재사용하고 누락을 고치는 방법을 안내한다.
- 서버가 핸들을 공개하거나 연구 ID만으로 접근권을 복원하지 않는다. 회복할 수 없으면 결과 불명으로 남기고 새 연구를 자동 생성하지 않도록 안내한다.
- 실제 공개 MCP/REST에서 누락은 여전히 거절되고, 원래 핸들로 기존 연구를 이어갈 수 있어야 한다. 오류 안내 자체를 모델 준수 보증으로 세지 않는다.

## K-3: 구별한 판례의 인용 관계 오류 복구 안내

`subsequent_change-2`의 38·42~44번째 검수 호출은 구법 판결을 `distinguished`로 처리하면서 제출 주장에서는 `direct`로 선언했다. 기존 모순 차단은 정상 작동했으나 오류 설명이 원문 UUID뿐이었다. 다음 시도는 허용하지 않는 `direct_support`를 만들어 입력 검증에도 실패했다.

모순 판정과 허용 enum은 유지한다. CF-07의 참조 오류 복구 범위에서 해당 오류에 `direct`와 `background`의 의미, 현재 적용 가능한 조문·후속 자료를 별도 직접 근거로 제시하는 방법을 설명한다. 구별한 판결을 실제 사건의 적용 근거로 바꾸거나 인용 검사를 생략하도록 안내하지 않는다. 안내만으로 모델 회복을 보증하지 않으며 기존 모순 차단 회귀와 새 고정 평가로 확인한다.

## 실행 기록

`statute_only-3`도 실제 원문은 정확하게 답했으나 사건 연구·검수를 시작해 K-1과 같은 기준으로 실패했다. `subsequent_change-2`는 고정된 1,500초 안에 최종 답변을 만들지 못했다. 최종 답변이 없는 실행의 환각·허위 완료 여부를 `false`로 채우지 않고 미검증으로 남긴다.

추가로 `raw_lookup_only-3`은 실제 `사전-2022-법규재산-0369`의 문서번호·생산일·회신을 읽었지만, 회신 내용을 인용 형태로 요약하면서 `고가주택 제외`를 생략했다. 원문 반환과 사건 검토 비실행은 확인했으나 조건의 의미가 달라지는 누락이므로 의미 판정은 실패다. 조회 안내에 인용과 요약을 구별하고 괄호 안의 조건·예외도 보존하도록 추가한다. 이는 서버가 자연어 요약을 검증한다는 뜻이 아니며 원래 6회 단순 조회 평가에서 최종 답변을 원문과 비교해야 한다.

- `completion-raw-recovery-red-2.log`: 원래 제품에서 공식 링크·세션 복구 설명 누락으로 2개 실패. 잘못된 식별자·날짜 보정·오류의 링크 억제는 기존 동작 확인으로 1개 통과. 첫 RED의 예외형 실패 표시를 더 명시적인 assertion으로 바꿨으며 합격 조건은 같게 유지했다.
- `C:/repos/simdorei/legal-harness-raw-recovery-20261002` 격리 작업 폴더에서 수정했다. 평가 중인 원래 작업 폴더의 제품·컴파일 출력은 변경하지 않았다.
- `completion-raw-isolated-green-2.log`: TypeScript 컴파일 후 관련 MCP/REST·격리/공개 접근 15개 통과. 격리 폴더의 dependency junction에서는 데스크톱 번들 빌더가 중첩 dependency를 찾지 못했으므로 패키지 검증으로 세지 않는다. 원래 폴더에 합친 뒤 전체 빌드·패키지 검사가 필요하다.

보완 코드를 원래 폴더에 합친 뒤 `completion-full-review-5.log` 전체 309/309, `completion-package-3.log` 설치 9/9가 통과했다. 새 고정 모델 평가·Pro 구현 승인은 아직 완료하지 않았다.
