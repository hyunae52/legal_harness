## 모델 시작 전 실행기 오류는 별도 보존

`raw_lookup_only-1`의 첫 실행 시도는 `ready.json`이 생성됐지만 아직 완성되지 않은 시점에 읽어 JSON 파싱에 실패했다. 모델 프로세스 시작 전이었고 모델 trace·최종 답변·원천 로그·MCP 로그가 전부 없었다. 원래 실패 폴더와 실행기 로그를 그대로 보존했다.

전체 원래 실행 시도가 종료된 뒤, 제품 `src`·`dist` 82개 파일과 고정 프로토콜 hash 불변을 확인했다. 실행기만 파일 존재가 아니라 유효한 readiness JSON을 최대 45초 기다리도록 수정했다. 빈 파일, 부분 JSON, 고정 대기 제한, 종료된 서버의 오래된 파일에 대한 네 Python 검사를 하나의 Node 테스트에서 실행하여 통과했다. 제품이나 1,500초 모델 제한은 바꾸지 않았다.

동일 입력 바이트·제품·프로토콜·모델·CLI로 해당 사례의 **첫 실제 모델 실행**을 별도 폴더에 기록했다. 이것은 실패한 모델 답변의 교체가 아니다. 전체는 실행 시도 25회, 실제 모델 실행 24회이며 복구 증거와 실행기 변경 전후 hash를 전체 근거 JSON에 첨부했다. 복구 실행은 예규의 문서번호·생산일·등록일·회신 조건·원문 오기를 정확히 보존했고 연구나 인터뷰를 시작하지 않았다.

## 추가 독립 검토 대상

`subsequent_change-2`, `amended_rule-3`에는 후속 판결을 `same_rule`이면서 `distinguished/background`로 분류하고 별도 법적 근거로 채택하지 않는다는 설명이 있다. 실제 후속 원문을 읽고 신법 적용 결론은 맞았으므로 원래 제한된 의미 oracle에서는 PASS지만, 이 분류가 후속 검색 의무를 우회할 수 있는지 별도 코드 검토가 필요하다. 이 PASS는 서버가 의미적 타당성까지 보장한다는 증거가 아니다.

사용자 요청에 따라 ChatGPT 웹의 SSS dot에 정확한 제품 커밋, 현재 검사 결과, 위 실패 경로와 후속 판결 분류 쟁점의 읽기 전용 분석을 요청했다. dot은 분석 착수를 응답했다. 분석 결과·실제 코드 접근 범위·Codex의 수용 또는 반박은 별도 기록에 남긴다. dot 요청을 기존 Pro 구현 승인으로 취급하지 않는다.

## 다음 수정의 경계

독립 고지의 평가·정리와 조사 의미의 변경을 구별할 최소 수정이 필요하다. 후보는 엄격히 제한된 범위 평가 갱신 경로다. facts/dates/issues, 요청·의존 트랙, 법령 앵커 또는 결론 의존성이 바뀌면 기존 revision 무효화가 유지돼야 한다. 고지의 문구가 바뀌었다는 이유만으로 언제나 안전하다고 판단할 수 없다.

양성 검사는 저장 원문과 완료된 검색을 유지한 채 이 정상 사례의 범위 정리를 닫는 것이고, 음성 검사는 사실·날짜·쟁점·의존 관계 변경, 다른 쟁점으로의 이동, 낡은 CAS, 누락·부분·실패 검색을 완료로 살리는 시도를 거절하는 것이다. 현재 실패를 PASS로 바꾸거나 새 세션으로 예산을 리셋하는 수정은 허용하지 않는다. 수정 전 실제 실패를 결정적 테스트로 재현하고 독립 분석을 대조한다.

제품 검사 309/309, 설치 패키지 9/9와 제품 커밋 CI는 재사용 가능하다. 이후 변경은 실행기와 그 전용 테스트, 근거 문서뿐이며 제품 소스는 그대로다. 새 커밋의 CI는 별도로 확인한다. **main 병합과 배포는 수행하지 않았다.**
