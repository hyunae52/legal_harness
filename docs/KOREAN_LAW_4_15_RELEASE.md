# korean-law-mcp 4.15.0 적용

법령 조회 제공자를 정식 npm 릴리즈 `4.15.0`으로 고정한다. 원본 코드는 수정하지 않고 기존 stdio 클라이언트를 유지한다. `package.json`, `npm-shrinkwrap.json`, `package-lock.json`의 버전을 함께 맞춘다. 세법 제공자는 기존 검토 포크 `2.0.0.post2`를 유지한다.

이번 릴리즈는 제명이 바뀐 법령의 연혁을 법령ID로 연결하고, 임의 사건일에 시행되던 조문과 별표를 조회한다. 원문 조회 성공은 개별 사건의 법적 적용 여부나 경과조치 해석을 확정하지 않는다.

## 검증

- 기존 `npm run review`, 패키지 설치 검증 및 runtime audit.
- `node scripts/law-release-smoke.mjs --live`: 국세기본법 사건일 조문, 개명된 소방 법령의 과거 버전, 도로교통법 시행규칙 별표, 과거 시점 별표를 실제 조회한다. 앞의 세 요청은 동시에 실행한다.
- GCE에서는 운영과 같은 Node 22 및 후보 설치본으로 위 검사를 실행하고 프로세스 메모리와 남은 메모리를 함께 기록한다.
- 작은 VM에서 기존 2 MiB / 총 8 MiB 제한이 큰 법령의 별표 조회를 막는지 확인한다. 4.15.0의 8 MiB / 총 24 MiB 한도는 후보 검증을 통과한 운영 환경에 명시한다. 동시 작업 3건과 응답 제한은 유지한다.

## 운영 전환과 기록

조회 엔진 교체는 일반 앱 자동 배포의 보호 범위다. 후보를 별도 경로에 설치하고 검증한 뒤, 운영 release manifest와 다운로드 제한을 함께 교체하고 재시작한다. 실제 MCP 조회 성공 후 자동 배포기의 승인된 법령 버전 및 manifest 해시를 갱신한다. 실패하면 이전 manifest·환경·배포기 설정을 복구한다. 기존 설치본은 롤백용으로 보관한다.

이후 main에 병합된 앱 패키지는 기존 자동 배포를 통해 배포한다. `/health`의 `mcp_release`는 선택된 법령 엔진 버전이고 `release_commit`은 우리 앱의 Git 커밋이다. 앱의 자체 버전과 조회 제공자 버전은 서로 다른 값이다.

일일 점검은 실제 서비스의 release manifest와 해당 실행 파일의 패키지 버전을 대조한다. 설치 버전이 바뀌면 새 버전의 npm 원본 커밋을 조회하므로 기존 `4.14.2`를 기준으로 `4.15.0` 업데이트 알림을 계속 보내지 않는다. 적용 직후 `check-upstreams.mjs`를 직접 실행해 기록 갱신을 확인한다. 예약 주기와 알림 정책은 그대로 유지한다.
