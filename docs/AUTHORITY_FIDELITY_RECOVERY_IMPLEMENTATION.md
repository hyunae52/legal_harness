# 원문 충실성과 검수 입력 복구 — 구현 계약

기준: `3517c432d6efb8f0b5ca50b5356fde8f03e09830` (제품 `c8edd6e`). pilot-n의 21/24 결과와 세 실패 원본은 보존한다. 후속 구현과 로컬 검사는 완료했고 SSS 코드 검수·원래 24회 모델 평가·출시는 아직 별도다.

## 목표와 경계

원문을 읽는 순간 질의·사실·회신 및 적용 예외를 함께 확인하도록 지원한다. 사건 답변의 부연 규칙에도 같은 원문 충실성 원칙을 적용한다. 검수 입력의 형식 오류는 그 경로의 실제 공개 입력 계약으로 고치고, 나머지 유효한 부분을 다시 만들어 잃지 않게 돕는다.

외부 LLM의 법률 의미를 서버가 인증하지 않는다. 새 모델/API, 조건 추출 정규식, 특정 법령 하드코딩, 자동 사실·인용 보충, 리뷰 입력 저장/패치 API를 추가하지 않는다. 연구 예산·TTL·검수 요건·기존 판정은 유지한다. 불가피한 조사 공백과 입력 실패는 최종 답변에서 정직하게 공개하며 허위 PASS로 바꾸지 않는다.

## 구현과 증거

- 원문 조회는 provider 결과와 분리된 `source_reading_guide`를 전달한다. 지원하는 실제 문자열 필드와 최종 응답의 JSON pointer만 열거하고, 64개를 넘는 참조는 `references_truncated`로 표시한다. 원문 자체를 절단·요약·복제하지 않는다.
- 사건 원문 선택과 검수 결과는 표현 계층에만 안내를 추가한다. 사용자가 요청한 개정·충돌 검토는 유지하면서 불필요한 별도 법률 단정을 줄이도록 안내한다. 자료·manifest·검수 상태·세션 바이트·예산은 바꾸지 않는다.
- 검수 요청의 형식 오류에만 해당 도구의 실제 공개 스키마를 결합한다. provider 내부 오류나 REST 요청 껍데기 오류에 review 스키마를 붙이지 않는다. 24개 진단과 전체 16,000바이트 상한, 동일 부모 스키마 중복 제거, 큰 조각의 명시적 생략을 적용한다. 스키마 조각 안의 제약은 잘라내지 않는다.
- `INVALID_INPUT`에는 이번 초안 미검수를, 실제 검수 응답에는 그 응답의 상태와 제한 답변 종료 경로를 표시한다. 이전 결과를 최종 답변의 PASS로 재사용하도록 승인하지 않는다.
